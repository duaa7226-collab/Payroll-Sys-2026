   320→6. REQUIRED CALCULATION LOGIC
   321→==================================================
   322→
   323→The salary engine must always use the ACTIVE rule set from the centralized Rules Control Center and must never rely on hardcoded payroll constants in scattered files.
   324→
   325→Support all of the following calculation strategies as editable rule modes:
   326→- days_prorated_mode
   327→- orders_based_mode
   328→- hybrid_mode_placeholder_for_future
   329→
   330→The active rule set must decide which mode is used.
   331→
   332→------------------------------------------
   333→6A. DAYS-PRORATED MODE
   334→------------------------------------------
   335→
   336→Use this when the active salary_divisor_mode = days_prorated_mode.
   337→
   338→Formulas:
   339→- Daily Base Rate = Monthly Base Salary / Standard Working Days
   340→- Daily Target Rate = Monthly Target Orders / Standard Working Days
   341→- Adjusted Base Salary = Daily Base Rate * Actual Working Days
   342→- Raw Adjusted Target Orders = Daily Target Rate * Actual Working Days
   343→- Adjusted Target Orders = rounded based on the selected rounding mode
   344→- Extra Orders = max(Completed Orders - Adjusted Target Orders, 0)
   345→- Missing Orders = max(Adjusted Target Orders - Completed Orders, 0)
   346→- Bonus Amount = Extra Orders * Bonus Per Extra Order
   347→- Missing Order Deduction = Missing Orders * Deduction Per Missing Order
   348→
   349→Gross Salary Before Other Penalties:
   350→- if Completed Orders >= Adjusted Target Orders:
   351→  Gross Salary Before Other Penalties = Adjusted Base Salary + Bonus Amount
   352→- else:
   353→  Gross Salary Before Other Penalties = Adjusted Base Salary - Missing Order Deduction
   354→
   355→------------------------------------------
   356→6B. ORDERS-BASED MODE
   357→------------------------------------------
   358→
   359→Use this when the active salary_divisor_mode = orders_based_mode.
   360→
   361→Core concept:
   362→- Monthly Base Salary is tied to Monthly Target Orders
   363→- Salary Per Order Rate = Monthly Base Salary / Monthly Target Orders
   364→- Default example: 2000 / 450 = 4.444444444444444 per order
   365→- If a driver scores 231 orders, then Base Salary Equivalent By Orders = 231 * 4.444444444444444
   366→
   367→Default formulas:
   368→- Salary Per Order Rate = Monthly Base Salary / Monthly Target Orders
   369→- Daily Target Rate = Monthly Target Orders / Standard Working Days
   370→- Raw Adjusted Target Orders = Daily Target Rate * Actual Working Days
   371→- Adjusted Target Orders = rounded based on selected rounding mode
   372→- Base Salary Equivalent By Orders = Completed Orders * Salary Per Order Rate
   373→- Selected Target Threshold = if Use Actual Working Days = yes then Adjusted Target Orders else Monthly Target Orders
   374→- Extra Orders = max(Completed Orders - Selected Target Threshold, 0)
   375→- Missing Orders = max(Selected Target Threshold - Completed Orders, 0)
   376→- Bonus Amount = Extra Orders * Bonus Per Extra Order
   377→- Missing Order Deduction = Missing Orders * Deduction Per Missing Order
   378→
   379→Default gross logic in orders_based_mode:
   380→- Gross Salary Before Other Penalties = Base Salary Equivalent By Orders + Bonus Amount - Missing Order Deduction
   381→
   382→Important rule:
   383→- Bonus and deduction remain active in orders-based mode unless the admin disables them from the Rules Control Center
   384→
   385→Optional alternative formula policies for admin selection:
   386→- strict_target_salary_policy:
   387→  - if Completed Orders = Selected Target Threshold, salary equals Monthly Base Salary
   388→  - if Completed Orders < Selected Target Threshold, salary = Base Salary Equivalent By Orders - Missing Order Deduction
   389→  - if Completed Orders > Selected Target Threshold, salary = Monthly Base Salary + Bonus Amount
   390→
   391→- linear_order_rate_policy:
   392→  - salary = Base Salary Equivalent By Orders + Bonus Amount - Missing Order Deduction
   393→
   394→The Rules Control Center must allow the admin to choose which orders-based formula policy is active.
   395→

   397→6C. COMMON PENALTY LOGIC
   398→------------------------------------------
   399→
   400→Total Other Penalties:
   401→- sum of all enabled and mapped penalty values from the workbook according to the active penalty rules
   402→
   403→This total may include:
   404→- acceptance penalties
   405→- contact penalties
   406→- stacking deduction
   407→- declined penalties
   408→- late penalty
   409→- no-show penalty
   410→- no-show special cities penalty
   411→- daily acceptance penalty
   412→- missed days penalty
   413→- rider balance deduction
   414→- car deduction
   415→- TGA deduction
   416→- traffic violations / traffic tickets
   417→- manual deductions
   418→- other mapped deductions
   419→
   420→Final Net Salary:
   421→- Final Net Salary = Gross Salary Before Other Penalties - Total Other Penalties
   422→
   423→Important:
   424→- the engine must normalize negative source deductions correctly and avoid double-sign errors
   425→- the engine must never use fixed values directly inside calculation code if those values belong to business rules
   426→- all such values must come from the centralized rules source
   427→- each payroll run must save a snapshot of the exact applied rules
   428→- later rule changes must not alter historical payroll run outputs
